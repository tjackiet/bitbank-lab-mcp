# サポート・レジスタンス分析

`analyze_support_resistance` が検出したラインを軸に、板（`get_orderbook`）で現在の厚みを補い、
シナリオまでまとめるスキル。MCP ツール（bitbank-lab-mcp）が使える前提で動く。

## 通貨ペアの決め方

- ユーザーが言った通貨の JPY 建てペアを使う（「ETH」→ `eth_jpy`、「エックスアールピー」→ `xrp_jpy`）。
- 指定がなければ `btc_jpy`。
- 対応は JPY 建てのみ。USDT 建てなどを求められたら、JPY 建てしか扱えないことを伝えて
  JPY 建てで進めてよいか確認する。未対応の銘柄はツールがエラーを返すので、そのまま伝える。
- 以下の `<pair>` は決めたペアに置き換える。

## 方針

- テキストのみで出力する。ツール実行後は中間説明を挟まず最終出力に進む。
- ★と形成情報は `analyze_support_resistance` の content をそのまま使う。独自計算・日付の推測はしない。
- 板は補足情報。板の厚みで★を上書きしない。

## ツール（この順に呼ぶ）

1. `analyze_support_resistance(pair=<pair>, lookbackDays=90, topN=3)` — ライン・★・形成情報の唯一のソース
2. `get_orderbook(pair=<pair>, mode=raw)` — 板の明細と取得範囲の確認
3. `get_orderbook(pair=<pair>, mode=pressure, bandsPct=[0.005, 0.01, 0.02])` — 帯域ごとの買い / 売り圧力
4. `analyze_sma_snapshot(pair=<pair>, type=1day, periods=[25, 75, 200])` — 任意。トレンドの補足

## 板の扱い

- 板で見えるのは現在値付近の一定範囲だけ。範囲はペアと板の厚みで変わる（BTC/JPY では通常 ±5〜6% 程度）。
  `mode=raw` の最も遠い買い価格・売り価格と現在値から、今回見えている範囲（下 −X% 〜 上 +Y%）を確かめる。
- 範囲内のラインは、その価格付近の板の数量を base 通貨（ペアの左側。`btc_jpy` なら BTC）の単位で書く。
- 範囲外のラインは「取得範囲外（過去実績で評価）」と明記する。板の数量を推測したり「不明」と書いたりしない。

## 表現ルール（厳守）

- 過去 7〜10 日で一度でも価格がラインを割り込んだ（レジスタンスなら上抜けた）場合、
  そのラインに「試され」「防衛中」「疲弊」を使わない。
- 代わりに「接触」「崩壊」「再割れリスク」「信頼性低下」を使う。
- 直近 7 日以内に崩壊したラインは★を 1 段階下げ、下げた理由を明記する。
- 出力前に、セクション間で「試され」と「崩壊」のような矛盾がないか確認する。

## 出力

必ず「📌 分析範囲について」から始める。前置きやツール結果の説明は書かない。

📌 分析範囲について — 板で見えている範囲（現在値から −X% 〜 +Y%）と、それより遠い価格帯は過去の反応実績で評価していること

## 1. 現在の状況（要約）— 現在価格、最重要ポイント、板バランス、トレンド
## 2. サポートライン — 検出分のみ。背景・板・意義。タイプ名は出さない
## 3. レジスタンスライン — 同様
## 4. シナリオ — 下抜け / 上抜け / レンジ（確率・トリガー・ターゲット・根拠）
## 5. 注意点
## 6. 構造図 — 上からレジスタンス → 現在 → サポートの簡潔なテキスト図（★・距離%・短い注記）

数値: 価格はカンマ区切り（円未満の刻みがあるペアはツールの表記の桁を保つ）、%は小数 1 桁、
板の数量は base 通貨単位で小数 1 桁。
