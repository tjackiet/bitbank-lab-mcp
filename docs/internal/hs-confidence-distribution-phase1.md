# H&S confidence 分布計測（issue #204 Phase 1・実測ログ）

`detect_hs.ts` の完成済み 4 経路が共有する
`confidence = finalizeConf((tolMargin + symmetry + per) / 3, type)` について、
[issue #204](https://github.com/tjackiet/bitbank-lab-mcp/issues/204) Phase 1 として
「`tolMargin` と `symmetry` が同じ `relDev(p0.price, p4.price)`（以下 rd）から作られており、
confidence が rd の 1 次式に潰れているのではないか」を実測で検証する。

**本ログは計測のみで、コードは 1 行も変更していない。** 式・閾値・軸構成の変更は Phase 2 以降で判断する。

## 結論（断定）

1. **閉じた式は全件で成り立つ。** 4,349 行すべてで、丸め後 confidence は
   `round(clamp01(adj × (2 + per − rd × (1/tol_d + 1)) / 3), 2)` と**完全一致**（不一致 0 件）。
   丸め前の値も `base × adj` と最大誤差 3.3e-16（浮動小数の丸めのみ）。**issue の読み違いは無い。**
   `1hour` / `per = 0.6` / strict に代入すると issue 本文どおり `confidence = 0.953333 − 7.7 rd` になり、
   #198 で増えた 4 件も rd・式の値・丸め後 confidence の全桁で再現した（[計測 1](#計測-1-閉じた式が全件で成り立つか)）。
2. **`per` は H&S では定数ではない。** #199 Phase 1（PR #203）の triple では 109 行全件が `per = 0.6`
   だったが、H&S では `0.6 / 0.7 / 0.8 / 0.9` の 4 値すべてが実測に出る。実データ B の
   ネイティブ時間足（`1hour`）だけに絞っても 89 構造中 **14 件（15.7%）が `per = 0.8`**。
   その帰結として**理論上限は時間足ではなく `per` で決まり**、`per ≥ 0.8` では `finalizeConf` の
   1.0 クランプが実際に効く（構造単位 22 件 / 生 248 行が `base × 1.1 > 1`）。
   「上限は 0.95」が成り立つのは `per = 0.6` の行だけ（[計測 2](#計測-2-時間足別の上限と通過帯)）。
3. **`MIN_CONFIDENCE.head_and_shoulders = 0.7` は 1 度も参照されていない（＝通過条件が存在しない）。**
   `detect_hs.ts` は `patterns/config.js` を **import していない**。`MIN_CONFIDENCE` を読むのは
   `detect_triples.ts` の 4 箇所（`triple_top` / `triple_bottom` のみ）だけで、
   `head_and_shoulders` / `inverse_head_and_shoulders` / `double_top` / `double_bottom` の 4 エントリは
   **定義されているが誰も読まない**。実測でも標準コーパスの構造単位 170 件中 **6 件（3.5%）が
   `confidence < 0.7` のまま出力**されており（最小 0.62）、うち 3 件は実データ B のネイティブ `1hour`。
   仮に配線した場合の rd 閾値は `1hour` / `per = 0.6` で **3.290%** で、issue 本文の 3.29% と一致する
   （per = 0.6 の 1hour 1,386 行で「丸め前 conf < 0.7 ⇔ rd > rd*」の反例 0 件）。
4. **relaxed 経路は 1 件も accept していない。** 940 ケース中、relaxed が走ったのは
   `head_and_shoulders` 764 回 / `inverse_head_and_shoulders` 800 回だが、**accepted は 0 件**。
   したがって「strict と relaxed を分けて集計する」という計測 2 の要件に対し、**relaxed 側は空**で、
   relaxed 固有の式（分母 `tolerancePct × factors.shoulder`、`base × 0.95`）は本コーパスでは
   一度も実行されていない。以降の分布はすべて strict。
5. **追加軸の候補は「分散が無い」ではなく「rd と重複する / 取れない」で落ちる。**
   issue が分散消失を疑った (b) ネックライン水平度は**潰れていなかった**（0.0000〜0.0499 でほぼ一様）が、
   **rd との相関が 0.66**（ネイティブ `1hour` で 0.725）で新規情報が薄い。逆に、
   (d) `retracementRatio` は rd とほぼ直交（全体 r = 0.01）で分散も広く、
   (c) 時間的対称性も分散が広い（0.056〜1.000）。(e) ブレイク品質は
   **算出できるのが 41.8%** かつ**そのうち 69.0% が 1.0 に飽和**していて弱い
   （[計測 3](#計測-3-追加軸の候補に実際に分散があるか)）。

### 「時間足」はパラメータのラベルであってリサンプリングではない（重要な限界）

標準コーパスは 1 本の価格系列に対して `tf` を差し替えて呼ぶ組み方で、**足を再集計しない**
（CHANGELOG の #131 以降の回帰比較と同じ手順）。`tf` が変えるのは
`swingDepth` / `minBarsBetweenSwings` / `tolerancePct` / `headProminencePct` / `sizeThresholds` だけで、
`periodScoreDays` に渡る `structureRange` は**系列の実際の `isoTime` 間隔**から出る。

したがって「`1min` 行」は *1 分足の実データ* ではなく *1 分足のパラメータを 1 時間足データに当てた結果* で、
特に `headProminencePct`（`1min` = 0.11% / `4hour` = 1.63%）が 15 倍違うため
[計測 3 (a)](#a-頭の突出度の余裕) の時間足間比較はこの影響を強く受ける。
**解釈の錨には「ネイティブ時間足サブセット」**（実データ B × `1hour` = 89 構造、
実データ A × `1day` = 2 構造）を使い、全体表は補助として読む。

### 手法メモ

- `tolMargin` / `symmetry` / `per` は `detect_hs.ts` が使うのと同じ関数（`relDev` / `clamp01` /
  `marginFromRelDev` / `periodScoreDays` / `finalizeConf`。`regression.ts` / `helpers.ts` から無改変で
  import）で、出力パターンの `pivots[0..4].price` と `structureRange.start/end` から再計算した。
- strict / relaxed の判別は `_fallback`（relaxed のみ `relaxed_hs_x1.6_0.6` 等が付く）で行う。
  実測では relaxed が 0 件だったため、以下の表はすべて strict。
- `retracementRatio` は出力の `structureGate.retracementRatio`（`applyReversalGate` が 4 経路すべてで
  返す値。`buildStructureGate` が 4 桁に丸めて載せる）をそのまま使う。**再計算していない。**
- ブレイク品質は doubles の `breakoutQualityScore` と同じ式
  `clamp01(excess / patternHeight)` を、H&S 用に `patternHeight = |頭の price − ブレイク足時点のネックライン|`
  として計算した（`breakoutTarget` の射影が使うのと同じ高さ）。doubles は「2 山の平均 − ネックライン」を
  高さに使うが H&S に対応物が無いため、**この定義の差は Phase 2 で軸を切り出す際に決め直す必要がある**。
  ネックライン値は strict の傾きつき線 / relaxed の水平線のどちらでも `necklineAt(neckline, breakoutIdx)`
  で取れるので、経路をまたいで同じ式で出せる。
- 件数は 3 段階で報告する。**生の行数**（オプション 8 通り × `swingDepth` × 時間足の重複を含む）、
  **構造単位**（`(series, tf, type, 5 点の idx)` で重複排除）、**`globalDedup` 後**
  （`detect_patterns.ts` と同じ順序で全 6 検出器を連結してから `globalDedup` を適用し、H&S 系だけ数える）。
  分けて出す理由は #203 と同じで、同じ 5 点を複数の窓・複数のパラメータが拾うため。

## 計測 1: 閉じた式が全件で成り立つか

### 一般形

```
tol_d    = strict ? tolerancePct : tolerancePct × factors.shoulder
adj      = strict ? 1.1 : 1.1 × 0.95        (= 1.045)
raw      = adj × (2 + per − rd × (1/tol_d + 1)) / 3
confidence = round(clamp01(raw), 2)
```

`tolMargin = clamp01(1 − rd/tol_d)` と `symmetry = clamp01(1 − rd)` の**クランプが外れている限り**
`tolMargin + symmetry = 2 − rd × (1/tol_d + 1)` なので上の 1 次式になる。

### 検算結果

| 検証 | 結果 |
|---|---|
| 丸め後 confidence の不一致 | **0 / 4,349 行**（max &#124;Δ&#124; = 0） |
| 丸め前 `raw` と `base × adj` の差 | max &#124;Δ&#124; = **3.3e-16**（浮動小数の丸めのみ） |
| `tolMargin` の下限クランプ（0 に切られた行） | **0 件**（`rd / tol_d` の最大が **0.9692 < 1**。肩ゲート `min(tolerancePct, HS_SHOULDER_MAX_PCT)` が先に効くため構造的に起きない） |
| `symmetry` の下限クランプ | **0 件**（rd の最大が 0.0465 なので `1 − rd > 0`） |
| `clamp01` の上限（`tolMargin = symmetry = 1`）に触れた行 | 48 行 / 構造 3 件。いずれも **rd がちょうど 0**（合成 fixture で両肩の終値が完全一致）。式の切り詰めではなく境界値 |
| `finalizeConf` の 1.0 クランプ（`raw > 1`） | **248 行 / 構造 22 件**。すべて `per ≥ 0.8`（内訳 `per=0.8` 128 行 / `per=0.9` 120 行）。`raw` の最大は 1.06333 |

**`raw > 1` の 248 行では 1 次式が上で頭打ちになる**（`confidence` が 1.00 に張り付き rd に反応しなくなる）。
それ以外の 4,101 行では丸めを除いて完全な 1 次関数。

## 計測 2: 時間足別の上限と通過帯

### strict / relaxed の分離 — relaxed は実測 0 件

| | `head_and_shoulders` | `inverse_head_and_shoulders` |
|---|---:|---:|
| relaxed が走ったケース（strict が 0 件だったケース） | 764 / 940 | 800 / 940 |
| relaxed が accept した件数 | **0** | **0** |

relaxed の棄却理由（`RELAXED_FACTORS` 末尾の段のみ積まれる。#174）:
`relaxed_shoulders_not_near:cap` 240 件 / `relaxed_shoulders_not_near:both` 64 件 /
`relaxed_neckline_not_horizontal` 64 件。`fallback_relaxed`（accepted）は 0 件。

**したがって relaxed 固有の式（分母 `tolerancePct × factors.shoulder`、`base × 0.95`）は
本コーパスでは 1 度も実行されていない。** 以下の実測値はすべて strict。
relaxed の理論値だけ参考として併記する。

### `per` の分布（構造単位）

`periodScoreDays` は `d < 5日 → 0.6` / `d < 15日 → 0.8` / `d < 30日 → 0.9` / それ以外 → 0.7。

### 理論上限（rd → 0）は `per` で決まる

| `per` | strict `raw` | strict 丸め後 | relaxed `raw`（×0.95） | relaxed 丸め後 |
|---:|---:|---:|---:|---:|
| 0.6 | 0.95333 | **0.95** | 0.90567 | 0.91 |
| 0.7 | 0.99000 | **0.99** | 0.94050 | 0.94 |
| 0.8 | 1.02667 → clamp 1.0 | **1.00** | 0.97533 | 0.98 |
| 0.9 | 1.06333 → clamp 1.0 | **1.00** | 1.01017 → clamp 1.0 | 1.00 |

**上限は `tolerancePct` に依らない**（rd → 0 で `tolMargin → 1` になるため）。時間足が効くのは
**傾き**だけで、上限を動かすのは `per` のみ。実測 confidence の最大値は、**検出があった 7 時間足
すべてで 1.00** に達している（いずれも `per ≥ 0.8` の構造を含むため）。

| `30min` | 0.060 | −6.478 | 3.91% | 4.48% | **5.04%** | **5.61%** | 0.050 | 0.63 | 0.68 |
| **`1hour`** | 0.050 | **−7.700** | **3.29%** | 3.77% | 4.24% | 4.72% | 0.050 | 0.57 | 0.62 |

- **`1hour` / `per = 0.6` の rd\* は 3.290%** で issue 本文の 3.29% と一致。
  per = 0.6 の行だけを取って「丸め前 conf < 0.7 ⇔ rd > rd\*」を検算した結果、
  `1min` 460 行 / `5min` 417 行 / `15min` 250 行 / `30min` 221 行 / `1hour` 1,386 行 / `4hour` 450 行の

  **通過帯の下端を決めているのはこれで、`MIN_CONFIDENCE` ではない**（次節）。

### `MIN_CONFIDENCE.head_and_shoulders = 0.7` は配線されていない

`config.ts:15` に定義はあるが、**`detect_hs.ts` は `patterns/config.js` を import していない。**
`MIN_CONFIDENCE` を読むのはリポジトリ全体で `detect_triples.ts` の 4 箇所だけで、
参照されるキーは `triple_top` / `triple_bottom` のみ。
`head_and_shoulders` / `inverse_head_and_shoulders` / `double_top` / `double_bottom` の 4 エントリは
**定義だけあって誰も読まない**（H&S の形成中経路が使う `FORMING_MIN_CONFIDENCE = 0.5` は
`detect_hs.ts` のローカル定数で、`MIN_CONFIDENCE` とは別物）。

実測でも 0.7 未満がそのまま出力される:

| 集合 | n | `confidence < 0.7` |
|---|---:|---:|

### (b) ネックラインの水平度

**issue の予想（`validateHorizontalNeckline` の hard gate 0.05 で分散が潰れている）は外れ。**

### (d) `retracementRatio`

**rd と最も直交する軸**（全体 `r(rd) = 0.01`）。構造ゲートの帯 `[RETRACEMENT_MIN, RETRACEMENT_MAX] = [0.2, 0.9]`


doubles と同じ `retracementScore`（帯の中央で 1・端で 0）に換算すると
min 0.011 / p25 0.259 / med 0.569 / p75 0.734 / max 0.975 / mean 0.504 で、**0〜1 をほぼフルに使う**。

**欠損は 81 / 857（9.5%）。** `applyReversalGate` は 4 経路すべてで呼ばれるが、
`validateReversalStructure` には `retracementRatio` を計算せずに `ok: true` で素通しする経路が 1 つある
——`findPriorExtreme` が先行極値を見つけられない場合の `skipped: 'no_prior_extreme'`
（`structural.ts:923`）。この経路では `priorExtreme` も `necklineCrossIdx` も無いため
`buildStructureGate` が `undefined` を返し、**パターンに `structureGate` 自体が付かない**。
Phase 2 で軸に採るなら**欠損時の扱い（doubles と同じく「平均から除外」か、既定値か）を決める必要がある。**

**全体とネイティブで符号ではなく強さが変わる**ので、Phase 2 の判断はネイティブ側の値で見ること。

### (e) ブレイク品質

**2 つの理由で弱い。**

1. **算出できるのが 358 / 857（41.8%）だけ。** `near_completion` 499 件は未ブレイクなので原理的に出せない
   （ネイティブ `1hour` では 34 / 89 = 38.2%）。doubles と同じ「平均から除外」の扱いが要る。
2. **算出できた中の 69.0%（247 / 358）が 1.0 に飽和。** `clamp01(excess / patternHeight)` の上限に
   張り付いており、上側の判別力がほとんど無い。十分位（ネイティブ `1hour` 34 件）:

```
0.343 0.416 0.610 0.613 1.000 1.000 1.000 1.000 1.000 1.000 1.000
```

ネイティブ `1hour` でも 21 / 34（61.8%）が 1.0。飽和していない側（< 0.5）は全体で 59 件しか無い。

なお本計測の `patternHeight` は `|頭 − ブレイク足時点のネックライン|` で、doubles の
「2 山の平均 − ネックライン」とは定義が違う（[手法メモ](#手法メモ)）。**H&S では頭がネックラインから
最も遠い点なので分母が大きくなり、飽和は本来より少なめに出ているはず**。それでも 69% が 1.0。

## Phase 2 への含意（本 Phase では決定しない）

- **`symmetry` の非寄与は H&S でも triple と同じ**（レンジ幅 0.047 に対し `tolMargin` は 0.969）。
  `tolMargin` と同じ rd から作られている以上、独立な軸として機能していないことは実測でも確認できた。
- **`per` は triple と違って定数ではない。** 「`per` をバー数基準に置き換える」という #199 の
  問題意識をそのまま H&S に持ち込むと前提が違う——H&S では `per` が実際に 4 値を取り、
  `per ≥ 0.8` では `finalizeConf` の 1.0 クランプが効いて **confidence が rd に反応しなくなる**
  （248 行 / 22 構造）。「上限 0.95」は `per = 0.6` の場合のみ。
- **`MIN_CONFIDENCE.head_and_shoulders` は配線されていない。** これは軸構成とは独立の欠陥で、
  「軸を増やして分布を作り直す」前に、**そもそも閾値を効かせるのか**を決める必要がある
  （効かせるなら `double_top` / `double_bottom` の 2 エントリも同じ状態にあることに注意）。
- **relaxed 経路は本コーパスでは 1 度も accept していない。** relaxed 側の式を変える提案は、
  **効果を実測できるコーパスが今は無い**という前提で評価すること。
- 軸候補の実測順位（rd からの独立性 × 分散 × 可用性）:
  (d) `retracementRatio` > (c) 時間対称性 > (a) 突出度の余裕 > (b) ネックライン水平度 > (e) ブレイク品質。
  (b) は「分散が無い」ではなく「rd と重複する」で下がり、(e) は「欠損 58% + 飽和 69%」で下がる。
- Phase 2 の共通前準備（`retracementScore` / `breakoutQualityScore` の共有モジュール切り出し）は
  **#199 候補 1 と共通**で、先に着手するほうでまとめて切り出す（issue #204 の記載どおり。Phase 1 では触らない）。
