## 1. 読み方

### 1-1. 何を測っているか

`TARGET_REACH_MAX_BARS` = 60 の根拠（#210）は **到達済み 2,576 行の初到達バー数のうち 60 本以内が 96.3%**。
これは**到達済みケースの条件付き分布**で、次の 2 つは測っていない:

- **到達率** — ブレイクしたが到達しなかったものを分母に入れた割合。
- **帰無との比較** — 同じ距離のターゲットを「任意のバー」に置いたときにどれだけ届くか。

本 Phase はこの 2 つと、**到達が自力か別パターン経由か**を実データで測る。

### 1-2. 窓と系列を分ける（この計測の要）

**検出はローリング窓で、到達の走査は系列全体で行う。** 窓は「その時点で何が検出されるか」を
決めるだけで、ブレイク後に実際に何が起きたかは凍結 fixture 側に全部入っている。
したがって `avail` / `firstReach` / `bodyBackInside1_2` は**窓の終端に依存しない**——
同じ実体ならどの窓で拾われても同じ値になる。**ローリング窓は構造単位を増やすためだけに使う。**

### 1-3. 量の定義

| 量 | 定義 |
|---|---|
| イベント | accepted パターン 1 件のブレイク。`breakoutBarIndex ?? breakout.idx ?? confirmation.idx` と `breakoutDirection` と `breakoutTarget` が**3 つとも揃う**もの |
| ブレイク価格 | **ブレイク足の終値**。`dist` = `\|target − breakoutPrice\|` |
| `avail` | ブレイク足の後に**系列**に残る本数。60 本揃うイベントだけを到達率の母集団にする（揃わないものは**打ち切り**として別集計。未到達と混ぜない） |
| `firstReach` | ブレイク足を 0 本目として `low ≤ target`（down）/ `high ≥ target`（up）を初めて満たす本数。**上限は 60 ではなく系列末尾まで**——実測で 72 / 83 / 99 / 101 本の到達が実在する |
| `otherBreakoutsBefore` | **同一系列内**で、同じ実体集合に属する他イベントのブレイク足が `(このブレイク, 初到達)` に入るもの。未到達なら `(このブレイク, +60]` |
| `selfReach` | `firstReach` が有限かつ `otherBreakoutsBefore` が空 |
| `bodyBackInside1_2` | ブレイク後 1 本目**または** 2 本目の終値が、ブレイクしたラインの**内側**に戻ったか |

### 1-4. 数え方を混ぜない

| 単位 | 定義 |
|---|---|
| 延べ | accepted な出力 1 件を 1 |
| **実体** | `(timeline, type, ブレイク足の絶対時刻, 方向, target を丸めた値)`（issue #288 の定義） |
| 値動き | 実体キーから `target` を落としたもの。**独立な標本数の上限** |

**母集団を pool しない**（#219）。実データ 1hour（B / C / D）は同じ 1 時間足履歴の重なる窓なので、
**実体は絶対時刻で 1 本の timeline に畳んである**——系列別に数えると同じ値動きを最大 3 回数える。
実データ A（1day）・合成 fixture は別の表。

**実体キーは `target` を含むので、同じ値動きでも窓の長さでパターン高さが変わると別実体になる。**
B / C / D は重なる履歴なので常に起きる。§4 の n は実体で数えているが、
**独立な標本数の上限は値動きの方**で、SE はその意味でも楽観的。

### 1-5. 代表系列の決め方

実体は複数の系列に現れうる（同じ絶対時刻のブレイクが B にも D にもある）。
`avail` は系列によって変わる（B の末尾に近ければ残りが少なく、D なら多い）ので、
**代表はコーパス順（A → B → C → D、各系列内は窓の短い順）で最初に見た系列**に固定した。
「残りが一番多い系列を採る」にすると母集団が実質 D に寄るので採らない。

### 1-6. `status` の 2 系統（issue 本文の食い違い）

issue #288 本文は 2 箇所で違うことを言っている:

- 「イベントの抽出」節 — **accepted パターン（`status: invalid` / `forming` は除く）**。
- 「自己検算」節 — 予備監査の値（実体 40 / 母集団 27 / 到達 18 / `firstReach > 20` の 6 件）。
  この 6 件のうち 3 件（`triangle_descending@22` / `@37` / `@37`）は**すべて `status: 'invalid'`**
  （下降三角形が上に抜けた形）なので、**accepted だけに絞ると 1 つも再現しない**
  （同じ切り出しで実体 24 / 母集団 16 / 到達 10 になる）。

どちらか一方を採ると「本文どおりにしたら検算が落ちる」か「検算を通したら本文と違う母集団」に
なるので、**両方を別ユニットとして出した**。主表は本文の定義どおり **accepted のみ**。
**`invalid` を出力から締め出しているわけではない**点に注意——`detect_patterns` は
`includeInvalid: true` で `invalid` を返し、そのとき `targetReachedPct` も一緒に出る。
つまり**走査窓の上限は `invalid` なパターンにも効いている**。どちらで判断するかは Phase 2。

### 1-7. 自己検算

`runSelfCheck` が**数字を 1 つも出す前に**走り、実データ全系列 × ネイティブ時間足 ×
既定 `swingDepth` × フル窓で予備監査の値（実体 40 / 母集団 27 / 到達 18 /
`firstReach > 20` の 6 件が `triangle_descending@22, 37, 37` / `rising_wedge@40, 40` /
`triangle_ascending@47`）を再現しなければ例外になる。

**issue 本文は「実データ B / C / D の全 365 本窓」と書いているが、実体 40 に届くには
実データ A（1day 90 本）の 4 件が要る。** A の `avail` は 8 / 9 / 43 / 44 でどれも母集団に
入らないので、**27 / 18 / 6 は B / C / D だけで測ったときと完全に一致する**。
この検算だけは `invalid` / `expired` を含む母集団で行う（§1-6）。

**自力到達だけは 1 件ずれる**（予備監査 12 に対し本スクリプト 11）。
`otherBreakoutsBefore` の「同一系列」を、絶対時刻で畳んだ実体に対してどう解決するかが
issue 本文で確定していないため。**質的な主張（この切り出しでは自力到達の max が 20 本で、
20 本超の到達は全件が別パターン経由）はそのまま成り立つ。**

### 4-1. 読み方

- **`n` は実体の数で、独立な標本数ではない。** 実体キーは `target` を含むので、同じ値動きが
  窓の長さ違いで複数の実体になる（§1-4）。独立な標本数の上限は**値動き**の方。
- **帰無の `m`（起点バー数）は大きいが、起点は重なっている。** 60 本先まで見る窓を 1 本ずつ
  ずらしているので、隣り合う試行はほぼ同じ値動きを見ている。**二項 SE は「同じ本数の独立試行
  だったら」という下限の目安**で、真の分散はこれより大きい。
- したがって**差の SE も下限**。「差が SE より小さい」は「差が無い」の十分条件ではないが、
  **差が SE 以内なら『上回った』とは言えない**とは言える。

### 4-2. 実測が言っていること

**どの N でもパターン起点の到達率は帰無を上回っていない。** 主表（n = 38 / m = 11,590）の差は
N = 5 / 10 / 20 / 30 / 60 で −5.2 / −8.5 / −0.8 / −4.9 / −8.3 pt、差の SE は 5.5 / 5.9 / 7.6 / 7.7 / 8.1 pt。
**差はすべて負**で、`|差|` が差の SE を超えるのは N = 10（−8.5pt / SE 5.9pt = 1.44 SE）と
N = 60（−8.3pt / SE 8.1pt = 1.02 SE）の 2 点だけ、残りは 1 SE 以内。
SE は下限の目安（§4-1）なので**「有意に低い」とも言えない**が、
**「パターンのブレイクだから届きやすい」という方向の証拠は 1 つも無い。**

`invalid` / `expired` 込み（n = 65 / m = 19,825）でも同じで、N = 20 / 30 / 60 の差は
+1.3 / −2.1 / +0.3 pt（差の SE 5.6 / 5.7 / 6.2 pt）。**符号が揃わない = 区別がついていない。**

これは**走査窓の長さの問題ではない**——N を 5 から 60 まで動かしても帰無との差が開かない。
`TARGET_REACH_MAX_BARS` をいくつにしても、`targetReachedPct` が「そのパターンだから届いた」を
意味しないことは変わらない。

## 7. 1day（実データ A）は評価不能
