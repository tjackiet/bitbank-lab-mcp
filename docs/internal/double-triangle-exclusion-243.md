# `double_*` × `triangle_*` / `wedge_*` の共存の実測（issue #243 Phase 1）

`scripts/measure_double_triangle_243.ts` の出力をそのまま貼ったもの（§7 以降）に、
目視判定（§5）と Phase 2 の推奨（§6）を足したメモ。**検出器のソースは 1 行も変更していない。**

母集団は **#242 実装後の作業ツリー**の出力集合。issue #243 本文の実例は #242 の経路ゲートで
既に `invalid` になっており、#243 が見たいのは「#242 の後にまだ残っている共存」だから。
§7 の各コーパスの「計測 4」に、#242 前（`b49a08e` = PR #241 のマージ）との差を出す。

## 1. 読み方

- **見ているのは出力集合だけ。** `detect_patterns` の縮小段（`globalDedup` → ライフサイクル
  絞り込み → `excludeTriplesSharingHsMainPoints`）を通した後の `data.patterns` 相当を突き合わせる。
  検出器の内部にフックは入れていない——`mutual-exclusion.ts` の設計原則
  「排他の根拠は呼び出し側が実際に受け取る出力集合に閉じる」と母集団を揃えるため。
- **共存ペア** = accepted（`completed` / status 無し）な `double_*` と、期間重複が **70% 以上**
  （`globalDedup` と同じ基準・同じ式）の `triangle_*` / `wedge_*` の組。継続側は status を問わない。
- **構造** = `(系列, 時間足, double の type と構成点 idx, 継続側の type と構成点 idx)` で畳んだ単位。
  オプション 8 通りと、同じピボット列を生む `swingDepth` の重複を除く。
- **価格系列上の組** = さらに時間足と継続側の窓の伸び縮みを畳んだ単位
  （`(系列, double の type と構成点, 継続側の type)`）。**排他ルールが実際に相手にするのはこちら。**
- 「時間足」は**パラメータ組の名前で再サンプリングではない**（#211 / #216 / #242 と同じコーパスの
  組み方）。`btc_jpy_1day_2026` を `1hour` のパラメータで走らせた行が出るのはそのため。
- コーパスは **プールしない**（#219）。標準 800 / 実データ B / C / D を別表で見る。

### 5-1. 判定の根拠（「両方成立」以外の 4 件）

**#1（三角形が正しい）** — 合成 fixture `descending_triangle_invalid` は、水平な床 97 を idx 4 / 10 /
14 / 18 / 22 の **5 回**叩き、天井が 133 → 128 → 123 → 118 と切り下がり、idx 24 で**上抜けて否定**
される形。`double_bottom 18-20-22` はその床の 5 タッチのうち**最後の 2 つ**と間の 1 つの天井を
切り出したもので、区間の選び方に構造的な理由が無い。三角形が形の説明として正しく、
`status: 'invalid'` が「継続の読みが否定された」ことを既に申告している。
（同区間には `inverse_head_and_shoulders 14-16-18-20-22` も出ており、**同じ床の 3 通りの読み**が
並ぶ。H&S × double は #243 の対象外だが、共存が double × triangle に限らないことの実例。）

**#3（ダブルが正しい）** — `rising_wedge` は idx 25〜45 の入れ子で、下抜け @45（終値 10,121,318）
の**次の足 idx 46 で終値 10,537,591 まで戻して否定**されている。外側の `double_bottom 7-17-33`
は idx 53 でネックライン 10,626,152 を上抜け（終値 10,849,999）、そのまま上昇が続く。
継続側のブレイクが 1 本で否定され、反転側の読みが実現しているので double が正しい。

**#16（三角形が正しい）** — issue #243 本文の実例。idx 318 の安値 12,126,452 から
330 / 332 / 334 / 338 / 340 / 342 と安値が切り上がり（12,624,440 → 12,662,059）、
天井は 329 の 12,807,555 と 338 の 12,800,000 でほぼ水平——**上限 6 タッチの
アセンディングトライアングル**。`double_top` の「山2」idx 338 は**高値 12,800,000 / 終値
12,639,245** の足で、その終値はネックライン 12,617,594 のわずか **0.17% 上**。
つまり山2 はヒゲで、同水準判定を通したのは終値基準の偶然。しかも double のネックラインは
idx 334 の終値 1 点だけで張られており、6 回叩かれた切り上がりの支持線のほうが構造的裏付けが強い。

**#17（どちらも成立しない）** — `triangle_descending 329…353` は「水平な床」を要求する型なのに、
下限線が 12,645,422 → 12,472,242 と 1.4% 切り下がっており（実際の安値も 12,588,132 → 12,302,470）、
形として成立していない。相方の `double_top 329-334-338` は #16 で見たとおり終値の偶然に依存する読み。
この区間の正しい説明は「318〜342 のアセンディングトライアングルが 343 で下抜け、
344 の急落後に 346〜353 で底を作った」であって、どちらの出力もそれを表していない。

### 5-2. 判定 × 方向の組み合わせ（構造単位）

| 方向 | 構造 | 三角形が正しい | ダブルが正しい | 両方成立 | どちらも成立しない |
|---|---:|---:|---:|---:|---:|
| **逆**（期待方向が対立） | 3 | 2 | 1 | **0** | 0 |
| 同（期待方向が同じ） | 5 | 0 | 0 | 4 | 1 |
| 中立（対称三角形） | 9 | 0 | 0 | 9 | 0 |
| **合計** | **17** | **2** | **1** | **13** | **1** |

**期待方向が対立する組は 3 構造すべてが「どちらか一方だけが正しい」**、同方向・中立の
14 構造は 13 が「両方成立」。裁定すべき集合と裁定すべきでない集合が、方向の対立で完全に分かれている。

| 共有 | 構造 | 三角形が正しい | ダブルが正しい | 両方成立 | どちらも成立しない |
|---|---:|---:|---:|---:|---:|

| 2 点 | 5 | 1 | 0 | 4 | 0 |
| 0 点 | 1 | 0 | 0 | 1 | 0 |
| 判定不能（`wedge_*`） | 4 | 0 | 1 | 3 | 0 |

**共有数は判別しない。** 3 点すべてを共有する 7 構造（標準コーパス 5 + 実データ D 2）のうち
排他すべきなのは 1 だけで、5 は「両方成立」・1 は「どちらも成立しない」。
2 点共有の 5 構造でも 4 が「両方成立」。#218 が triple × H&S で使えた
「主構成点は 3 点しかないので 2 点以上の共有は同じ構造の別解釈」という論法は、

ほぼ全部拾うので、区間が重なれば double の 3 点は自然に含まれてしまう。

### 5-4. 実データ C と D で結果が違う理由（計測 5 の読み解き）

実データ C と D は `2026-08-21T04:00Z` 〜 `2026-09-04T13:00Z` の 346 本が重なり、
**D の idx + 19 = C の idx**。にもかかわらず**両方に出る共存構造は 0**（§7 の計測 5）。

`double_top` のほうは両方に同じものが出ている（C の `348-353-357` = D の `329-334-338`。
どちらも `swingDepth=6` で `completed`）。違うのは**勝ち残る `triangle_ascending` の窓**:

| | 三角形の窓（自系列の idx） | D の idx 空間 | 重複率 |
|---|---|---|---:|
| 実データ D | `316`〜`342`（26 本 / 下抜け @343） | 316〜342 | **93.3%**（共存する） |
| 実データ C | `336`〜`353`（17 本 / 下抜け @354） | 317〜334 | **40.0%**（閾値未満） |

C 側で D と同じ 26 本窓が出ないのは `globalDedup` に負けたからではない——`detectTriangles`
の段階で**その窓が評価されていない**。窓は `winEnd = windowSize` から `posStep` 刻みで
idx 0 に錨を打って進むので、取得窓が 19 本ずれると格子ごとずれる:

- `1hour` / 365 本の `windowSizes` は `[17, 26]`（`structuralFloorBars('1hour') = 17` から ×1.5）。
- `windowSize=26` は `posStep=4` で `winEnd ≡ 2 (mod 4)`。D の `winEnd=342` は該当するが、
  C で同じ値動きを覆う `winEnd=361` は `361 mod 4 = 1` で**格子に乗らない**。
- `windowSize=17` は `posStep=2` で `winEnd` が奇数。C の `winEnd=353` は該当するが、
  D で対応する `winEnd=334` は偶数で**こちらも評価されない**。

つまり**同じ値動きでも取得窓の長さが 19 本違うだけで、三角形の区間が変わり、重複率 70% を
跨いでしまう。** 重複率を排他の判定基準に使う設計は、この揺れをそのまま引き受けることになる。

## 6. Phase 2 への推奨（決定はしない）

### 推奨: **案 C（何もしない）**

根拠を 5 つ。

1. **裁定が必要な母数が足りない。** 排他すべきと判定できたのは **3 構造 / 3 価格組**
   （うち 1 つは合成 fixture、1 つは `wedge_*` で共有数が計算できない組）。#218 Phase 1 が
   「二重出力 18 ペア（共有 3 点 5 / 2 点 6 / 1 点 7）」という分布を根拠にできたのに対し、
   #243 は分布と呼べるものが出ていない。#218 の教訓
   （`triple-depth-ratio-218.md` — 構造 13 件では hard gate の根拠にならない）がそのまま当てはまる。
2. **案 A（共有数）は判別しない**（§5-3）。#218 と同じ「閾値を持たない」設計で書けるかという
   問いへの答えは **書けない**。#218 の「2 点以上」が閾値でなく規則そのものになれたのは
   *主構成点が 3 点しかない者どうし*の比較だったからで、構成点を 8〜16 点持つ三角形が相手だと
   「含まれるのが当たり前」になり、共有数は情報を持たない。
3. **案 B（`invalid` なら double を残す）は極性が逆。** 実測では継続側が `invalid` の
   3 構造（#1 / #16 / #17）のいずれでも double は正しくない
   （#1・#16 は三角形が正しい、#17 はどちらも成立しない）。
   `invalid` は「継続の読みが否定された」＝**その否定こそが反転の実体**という意味なので、
   同じ動きを double として二重に出す理由にはならない。案 B を入れると 3 件すべてで誤る。
4. **共存の 8 割は裁定すべきでない**（13 / 17 が「両方成立」）。排他を入れると、
   別スケールの正しい構造——大きな対称三角形の中の小さなダブル、ダブルの右足の中のウェッジ——
   まで消える。`globalDedup` の 70% は分母が短いほうの期間なので**入れ子でも 100%** になり
   （最小の短長比 25.0%）、「同じ区間」を判定する基準としてそもそも使えない。
5. **起票時の実例は #242 で既に既定パラメータでは消えている**（§3）。残るのは
   `swingDepth=6` を明示したときだけで、原因は型間排他の欠如ではなく
   #242 の経路ゲートが見るピボットが探索深さで変わることにある。

### 案 C を採るときに残る宿題（#243 の外）

- **`double_top 329-334-338` が `swingDepth=6` でだけ生き残る**件（§3）。#242 の経路ゲートを
  ピボットではなく足の高安で見る形にすれば深さ非依存になるが、それは #242 の範囲であって
  型間排他ではない。別 issue にするなら「経路ゲートの深さ依存」という表題になる。
- **`wedge_*` が `pivots` を出力しない**件。共存の 4 / 17 構造が「共有数を計算できない」に落ちる。
  Phase 2 でどの案を採るにせよ、構成点を持たない検出器がある限り
  「主構成点ベースの排他」は継続側の一部に適用できない。
- 同じ床を `triangle_descending` / `double_bottom` / `inverse_head_and_shoulders` の
  3 通りで出す例（§5-1 の #1）。共存は double × triangle に閉じていない。

### 案 A / B を採るなら追加で必要な計測

- 母数を増やす。実データ B / C は共存 0 件、実データ D は 2 構造なので、
  **現行のコーパスでは分布が取れない**。共存が起きる窓を狙って新しい実データ窓を足すか、
  合成 fixture を「反転と継続が同じ極値を共有する」形で設計するところから。
- 「期待方向の対立」を軸にするなら（§5-2 が唯一きれいに分かれた軸）、
  対立する組だけを集めた母集団で **どちらが勝つかの規則**を作れるかを測る必要がある。
  現時点の 3 件では三角形 2 / ダブル 1 で、勝者が一定でない。

## 決定: 案 C（何もしない）

本メモの Phase 1 を受けて、**`double_*` × `triangle_*` / `wedge_*` の型間排他は入れない**（issue #243 のコメント）。

- 排他すべきと判定できたのは 17 構造中 3 件（うち 1 件は合成 fixture、1 件は `wedge_*` で共有点数を計算できない）。ルールを決められる分布が無い。
- 案 A（共有点数ルール）は成立しない。三角形は区間内の極値をほぼ全部拾うので、区間が重なれば double の 3 点は自然に含まれる。
- 案 B は極性が逆。継続側が `invalid` の 3 構造すべてで double 側が正しくない。
- 起票時の実例は既定パラメータでは #242 で既に消えている。

宿題は別 issue に切り出した: #251（経路ゲートの `swingDepth` 依存。**案 3 = 深さ依存を仕様として文書化 + テストで固定**で決着）、#252（`wedge_*` が `pivots` を出力しない件）。計測スクリプトと本メモは、共存が起きる窓を狙った実データや合成 fixture が増えて母数が取れたときの再計測用に残す。
