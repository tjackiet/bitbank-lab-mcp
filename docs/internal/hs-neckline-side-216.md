# H&S の主構成点とネックラインの位置関係（issue #216・H&S 分。Phase 1 再計測 + Phase 2 実装ログ）

[issue #216](https://github.com/tjackiet/bitbank-lab-mcp/issues/216) の H&S 分。

> H&S 系の**主構成点（左肩 p0 / 頭 p2 / 右肩 p4）がすべてネックラインの正しい側にある**ことを要求する。
> `head_and_shoulders` なら全点が上、`inverse_head_and_shoulders` なら全点が下。等号は失格。

triple / double 側は [#223](https://github.com/tjackiet/bitbank-lab-mcp/pull/223) で
[実装済み](./neckline-side-gate-216.md)。H&S だけは「スカラー基準（`price`）と傾きつきの線基準
（外挿）で判定が反転しうる」ため **[#211](https://github.com/tjackiet/bitbank-lab-mcp/issues/211)
の結論待ちで保留**されていた。#211 が PR #239 でマージされ、`necklineAt` が全消費者
（ブレイク検出・スコアリング・ターゲット投影）の単一基準になったので保留は解消している。

**旧 Phase 1（[`structural-neckline-main-points-216.md`](./structural-neckline-main-points-216.md)）の
H&S の数値は #211 より前の基準・母集団で取ったもので、そのままでは使えない**（#198 と同じ事故を
避けるため無検証で流用しない）。本ログは `necklineAt` 基準で測り直した Phase 1 と、
その結果に基づく Phase 2 の実装記録を兼ねる。

## 結論

1. **頭 (p2) が誤った側にある候補は 0 件**（標準コーパス 800・実データ B 96 とも、
   H&S / 逆 H&S とも）。誤側に来るのは**肩だけ**で、落ちる 25 構造はすべて肩が原因。
2. **ゼロ近傍の集団は無い。** 逸脱量（パターン高さ相対）の最小は標準コーパスが **3.732%**
   （22,007 円）、実データ B が **1.504%**（3,857 円）で、**0〜1.5% は空**。
   旧 Phase 1 が挙げた「逆 H&S の最小 0.012%（31 円）」は**この基準では再現しない**
   （あれは #211 前のスカラー水準基準の値）。→ **triple / double と同じくゼロ許容で切れる。**
3. **ゲートで落ちるのは構造単位 25 件**（標準コーパス 14 / 実データ B 11）。
   すべて **strict 経路**で、relaxed 経路はゲート位置に到達した候補が **0 件**。
4. **`data.patterns` は延べ −20**（1,424 → 1,404）。内訳は削除 36 / 追加 16 で、
   追加は `globalDedup` の代表入れ替わり。**凍結ベースライン
   （`tests/fixtures/detect_patterns_1hour_data_patterns_baseline.json`。実データ B の
   `1hour` × 既定オプション）は 1 バイトも動かない**ので更新していない。
5. **`necklineProjectionHeight` の「高さ 0 以下ガード」との重複は実測 0 件**（下の 5 章）。

## 基準: `necklineAt(neckline, point.idx)` — 点ごとの値

triple / double のネックラインは水平スカラーなので 1 つの値で足りたが、H&S の strict 経路は
`p1` / `p3` の 2 点で張る**傾きつきの直線**。主構成点ごとに、その点の `idx` で `necklineAt` を
評価した値と比べる。`necklineAt` は #211 で `[p1.idx, p3.idx]` にクランプされているので、
実質的な比較相手はこうなる:

| 主構成点 | `idx` の位置 | `necklineAt` の実質的な意味 |
|---|---|---|
| 左肩 (p0) | `p1.idx` より前（区間の外） | クランプで `p1.y` に頭打ち＝**谷1 の水準と比較** |
| 頭 (p2) | `p1.idx`〜`p3.idx` の内側 | **真の内挿値**（傾きを反映） |
| 右肩 (p4) | `p3.idx` より後（区間の外） | クランプで `p3.y` に頭打ち＝**谷2 の水準と比較** |

**肩だけが「外挿した線」ではなく「近い方の定義点の水準」と比較され、頭だけが真の内挿値で
評価される。この非対称性は実装ミスではなく #211 の設計そのもの**——定義点の外側の値は
「教科書の直線を伸ばしたらこうなるはず」というモデル上の仮定で、実際のサポート /
レジスタンスの根拠が無い。**新しい基準は作らず、既に統一されている値をそのまま使う。**

`p1` / `p3`（ネックラインの定義点そのもの）は検査対象から外す。渡すと自分自身と比較する検査に
なり、`deviation === 0` で必ず失格する。

## 3. ゼロ近傍の細密ヒストグラム（0.1% 刻み）

**本 issue の分岐点**——ゼロに張り付いた集団があるなら、閾値なしの hard gate は
「連続分布を任意の位置で切る」ことになる（#214 の非恣意性テストと同じ見方）。

| コーパス | type | 0〜2% の分布（0.1% 刻み） | 2% 以上 | 最小値 |
|---|---|---|---:|---:|
| 標準 800 | H&S | **空** | 10 | **3.732%**（22,007 円） |
| 標準 800 | 逆H&S | **空** | 6 | **9.490%**（30,264 円） |
| 実データ B 96 | H&S | **空** | 7 | **13.393%**（71,817 円） |
| 実データ B 96 | 逆H&S | 1.5-1.6%:2 | 2 | **1.504%**（3,857 円） |

構造単位の逸脱量を昇順に並べると:

```text
標準 800:      3.732%×5  9.490%×2  11.715%×2  16.521%×4  18.769%  22.606%×2
実データ B 96: 1.504%  1.580%  2.650%  5.876%  13.393%×4  13.618%×2  21.591%
```

- **0〜1.5% は全コーパスで空。** 最小の 1.504% は絶対額 3,857 円で、丸め誤差の産物ではない。
- 実データ B の 1.504% / 1.580% / 2.650% は**同じ 1 点**（逆 H&S 左肩 idx 301。逸脱 3,857 円）を
  高さの違う 3 構造で正規化したもの。**物理的に別の誤側の点は全コーパスで 8 点しかない。**
- **旧 Phase 1 の「逆 H&S 最小 0.012%（31 円）」は再現しない。** あれは #211 前の
  **スカラー水準**（strict は 2 谷の平均 `nlAvg`）を基準にした値で、`necklineAt` に統一した
  今の基準では該当が消えている。旧ログの `clamped` 参考値（最小 5.089%）とも母集団が違うため
  数値は一致しないが、**「ゼロ近傍が空になる」という向きは一致**している。

→ **閾値（許容幅）を置かずにゼロ許容で切れる。** triple / double と同じ判断
（[`neckline-side-gate-216.md`](./neckline-side-gate-216.md) の「許容幅を置かない」）。

## 5. `necklineProjectionHeight` の「高さ 0 以下ガード」との重複（issue の依頼事項）

`necklineProjectionHeight` は「頭がネックラインを追い越した（高さ ≤ 0）なら target を出さない」
というガードを持つ。本ゲートは**同じ形の候補を hard reject する**ので範囲は広がる
（従来は「target を出さないだけで候補は残る」）。

**実測では重複は 1 件も起きていない。**

| | 標準 800 | 実データ B 96 |
|---|---:|---:|
| 頭 (p2) が誤側の候補 | **0** | **0** |
| 肩だけが誤側の候補（構造単位） | 14 | 11 |

`necklineProjectionHeight` の docstring にある「3 経路とも頭が 2 定義点の外側に来ないので
検出器経由ではガードに到達できない——標準コーパス 896 ケースでも発火 0 件」と**同じ結果**で、
本ゲートが落とす 25 構造は**すべて肩が原因**。したがって:

- 本ゲートは既存ガードの守備範囲を**実質的に奪っていない**（頭では発火しない）。
- 逆に既存ガードは本ゲートの後でも**到達不能なまま**（頭が誤側なら候補ごと落ちるので、
  高さ ≤ 0 で `undefined` を返す経路にはそもそも入らない）。**両方残す**——
  `necklineProjectionHeight` は export されて単体テストが直接叩いており（#208 / #210 の回帰）、
  ガードを外すと「値幅の計算が符号を無視しない」という保証がテストごと消える。

### 既存関数は変えていない

`validateMainPointsNecklineSide`（triple / double 用）は**スカラー 1 つを受け取る設計のまま**で、
シグネチャ・テスト・`view=debug` の出力形を 1 つも変えていない。線版は**別関数**にした。
戻り値の型（`MainPointNecklineSideResult` / `MainPointNecklineSideOffender`）と理由コード
（`peaks_below_neckline` / `valleys_above_neckline`）は**再利用**——`view=debug` の
`▼ reason 横断合計` を triple / double と H&S で揃えるため。

`structural.ts` は `detect_hs.ts` を import しない（現状 `regression.js` / `swing.js` にしか
依存しない片方向を崩さない）。`necklineAt` は**呼び出し側が関数として渡す**。

### `details` の形（`view=debug`）

`necklineSideDetailsFromAt` は **offender ごとに `necklinePrice`** を持つ:

```json
{
```

## 7. 限界

- **誤側の点は全コーパスで物理的に 8 点しかない**（標準 5 / 実データ B 3）。
  分布の「膝」や「空白帯」の議論はこの標本数の上での話で、旧 Phase 1 が
  `double` / `triple` について書いた「標本が薄い」という限界がそのまま付く。
- **relaxed 経路は挙動で検証できていない**（母集団 0 件）。配線は strict との対称性で入れてあり、
  テストはソースを読むトリップワイヤで固定している。
- 標準コーパスの「時間足」はリサンプリングではなく `resolveParams` に渡すラベル
  （#205 の同名の注記と同じ限界）。**結論はプール値で書いていない**（#219）。
