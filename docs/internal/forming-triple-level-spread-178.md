## 1. 読み方

- **`levelSpread`（価格相対）** = 形成中経路が実際に見ている量。主構成点 3 点の**終値**に
  `(max − min) / max` を掛けたもの。上限は
  `tolerancePct × FORMING_TOLERANCE_MULTIPLIER × FORMING_LEVEL_SPREAD_FACTOR`
  （1day 4.8% / 1hour 6.0%）。
- **`spreadRatio`（高さ相対）** = `levelSpreadMetrics` の比。主構成点のばらつき（**終値**）÷
  パターン高さ（**高安**）。完成済み経路の `validateLevelSpread` が `MAX_LEVEL_SPREAD_RATIO = 0.5`
  で上限を掛けている量で、**形成中には無い**。
- **`spreadRatio > 0.5` は「主構成点の水準帯が、そこからネックラインまでの押しより厚い」と同値**
  （`heightAbs = spreadAbs + 押し` なので）。§10 の §3-3 に 2 列を並べてある。
- **「完成仮説」の `spreadRatio`** = 最新足が第 3 ピボットとして確定したと仮定して、
  `current` の `extremePrice` にその足の**高安**を置いて測り直した比。**主指標とは別の量**
  （§5 に両向きの反例）。
- **「使用率」** = `実測 ÷ 上限`。大きいほうを律速とする（#244 と同じ読み方）。
- **「延べ / 構造 / 実体」の 3 段**:
  - **延べ** = 検出器が組み立てた候補 1 件（ケース × ローリング窓の終端ごと）
  - **構造** = `(系列, 時間足, type, peak1/peak2 の idx)` で畳んだ単位
  - **実体** = **絶対時刻**で畳んだ単位。**実データ B / C / D は独立系列ではない**——
    同じ btc_jpy 1 時間足履歴の重なる窓で、C は B の idx 181 から（B∩C = 184 本）、
    D は C の idx 19 から（C∩D = 346 本）始まる。**個数を語るときは実体で語る。**
- コーパスは**プールしない**（#219）。**時間足別の結論は実データ B / C / D（実 1hour 365 本）と
  実データ A の 1day だけから出す**（#178。標準コーパスの実データ A 96 は同じ 1day 90 本に
  `tf` ラベルを付け替えたもの）。標準コーパス（合成 704 + 実データ A 96）は参考値。
- **形成中は「最新足」の位置で結果が決まる**ので、固定窓 800 + 96×3 だけでは母集団が薄い
  （accepted な形成中 triple が 108 延べしか出ない）。実データ B / C / D それぞれについて
  **窓の終端を 1 本ずつずらすローリング**（末尾 60〜365 本 × 時間足 3 × `swingDepth` 4 = 3,672）を
  足してある。#244 の窓長スイープ（8 点）より密。
- ローリング窓は統合オプションを全 true の 1 通りに固定した。形成中経路の発火を左右するのは
  `includeForming` だけなので、8 通り回しても同じ候補が 8 回積まれる。

## 3. 問題設定（コードの事実）

`tools/patterns/detect_triples.ts` の形成中 2 経路:

```ts
const tripleTolerancePct = tolerancePct * FORMING_TOLERANCE_MULTIPLIER;   // × 1.2
const levelSpreadLimit  = tripleTolerancePct * FORMING_LEVEL_SPREAD_FACTOR; // × 1.0
...
const levelSpread = (levelMax - levelMin) / Math.max(1, levelMax);          // 分母 = 価格水準
if (levelSpread > levelSpreadLimit) → 'forming_peaks_not_level'
```

3 点は `peak1` / `peak2`（確定ピボット、`price` = 終値）と `current`（最新足の終値。ピボットではない）。
判定は**価格相対のみ**で、完成済み経路が持つ高さ相対の hard gate
（`validateLevelSpread` / `MAX_LEVEL_SPREAD_RATIO = 0.5`。#138 / PR #176）が無い。
実効閾値は 1day 4.8%（0.04 × 1.2）、1hour 6.0%（0.05 × 1.2）。

完成済み側は 2 段（`tolerancePct` の `nearAll` と `validateLevelSpread`）で、形成中側は 1 段。
**`detect_doubles.ts` の注記にある原則「形成中 ⊇ 完成済みの厳しさ」（形成中は完成済みより緩くて
よいが、完成済みが必ず落とすものを形成中が通す状態は避ける）が破れている**、というのが本件の形。

### 3-1. 破れは 1 箇所ではない（計測中に判明）

同じ「完成済みに配線済み・形成中に未配線」が `validateMainPointsNecklineSide`（#216 Phase 2）にも
ある。完成済みは strict / relaxed × top / bottom の 4 経路すべてで呼んでいるが
（`detect_triples.ts:336` / `:620` / `:900` / `:1165`）、形成中 2 経路には呼び出しが無い。

**本 issue の対象ではないが、主指標の解釈に直接効く**ので併記する（§8 / §7）。

### 3-2. 単調性ゲートは片側だけ（同じく計測中に判明）

`FORMING_STAIR_STEP_LIMIT` の判定は
`peak1 < peak2 < current`（triple_top の**切り上がり**）と
`valley1 > valley2 > current`（triple_bottom の**切り下がり**）しか見ていない。
**triple_top の単調な切り下がり / triple_bottom の単調な切り上がりは素通りする。**
§8 の #14（切り下がり 2.77%）と #23（切り上がり 1.52%）がその実例。

> **その後（#263）**: 両向きに直した。**閾値 `FORMING_STAIR_STEP_LIMIT`（2%）は据え置き**なので、
> 落ちるようになったのは #14（2.77%）だけで、**#23 は 1.52% で閾値の直下のまま残る**
> （#20 の切り上がり 1.86% も同じ。あちらは元から見ていた向き）。
> 実測は同スクリプトの §7。

## 4. 主指標 — 完成しえない形成中候補

### 4-1. 件数

| 単位 | `spreadRatio > 0.5` | 全体 | 割合 |
|---|---:|---:|---:|
| 延べ | 2,625 | 7,581 | 34.6% |
| 構造 | 78 | 111 | 70.3% |
| **実体（絶対時刻で畳んだ数）** | **34** | **48** | **70.8%** |

母集団別は §10 の §2。**標準コーパス 800 は 0 件**で、出るのは実データ 1hour だけ。

### 4-2. 分布に空白帯は無い

`MAX_LEVEL_SPREAD_RATIO = 0.5` を決めたときの基準（#214 / PR #176 の「分布の空白帯」）を
本件に当てると**不合格**。実データ 1hour の `spreadRatio` は
min 0.019 / p50 0.41〜0.51 / p90 0.61〜0.72 / max 0.9422 で、**0.5 の周辺に隙間が無い**
（§10 の §1）。ablation の効き方（0.5 → 消えた 2,625 延べ / 0.6 → 1,273 / 0.75 → 309 / 1.0 → 0）も
なだらかで、閾値を分布から決める余地がそもそも無い。

**したがって Phase 2 で `maxRatio` を独自に決める根拠は分布からは出ない。**
採れるのは「完成済みと同じ 0.5 に揃える」（案 A。根拠は分布ではなく**一貫性**）か
「何もしない」（案 C）で、**中間の値（案 B）は根拠を作れない**——これが本 Phase の
いちばん効く結果。

### 4-3. 主指標の解釈には 1 段の注意が要る

主指標は #169 の idiom（`current.extremePrice` = 終値）で測った `spreadRatio` だが、
**完成済みゲートが実際に測るのは第 3 ピボットの `extremePrice`（高安）**。
同じ足が第 3 ピボットとして確定したときの比（「完成仮説」）は別の量になる:

| 比較 | 延べ |
|---|---:|
| 完成仮説のほうが大きい | 160 |
| 完成仮説のほうが小さい | 990 |
| 同値 | 6,431 |

完成仮説で 0.5 を超えるのは **2,551 延べ**（形成中 idiom では 2,625 延べ）。
**延べは食い違うが、構造（どちらも 78）と実体（どちらも 34）は一致する**——閾値をまたいだ候補が
あっても、それは同じ構造の別の窓に吸収される。したがって §4-1 の件数は idiom の選び方に依存しない
（3 段の突き合わせは §10 の §2-2）。

### 4-4. その後どうなったか

ローリング窓で同じ `peak1`/`peak2` を後続の終端まで追跡した結果（§10 の §2-1）。
**形成中 triple に `expired` ステータスは無い**（`detect_doubles.ts` の形成中 double bottom に
だけある）ので、出るのは 3 通り:

| その後 | 構造 |
|---|---:|
| 後続の窓で **completed** として accepted になった | 25（うち 3 は高さ相対の棄却も出す） |
| 完成せず、完成済み経路の高さ相対ゲートで落ちた | 15 |
| 未完成のまま（窓の終端まで） | 38 |

**「完成した」25 構造のうち 3 構造は、完成の前後で高さ相対ゲートの棄却も出している。**
同じ 2 点から作られる 3 点目の取り方によって、通る窓と落ちる窓が両方ある。

## 5. 幾何の主張 — 両向きに動く（依頼文の主張は成立しない）

依頼文は「`current` が後にピボットとして確定したときの `extremePrice` は終値より外側になるので、
`spreadRatio` は確定後に上がる方向にしか動かない」と書いたうえで、
**#178 項目 4 の教訓（幾何の主張は反例を構成してから書く）に従って反例を試すよう指示**していた。
実測した結果、**両向きに動く**:

| 向き | 系列 | tf | sd | 終端 | type | 構成点 | 形成中 `spreadRatio` | 完成仮説 |
|---|---|---|---|---:|---|---|---|---|
| 上がる | `btc_jpy_1hour_2026_08` | 1hour | auto | 281 | triple_bottom | 242-249-281 | 0.8501 | **1.0711** |
| 下がる | `btc_jpy_1hour_2026_08` | 1hour | 2 | 312 | triple_top | 257-265-312 | 0.5708 | 0.4010 |

成り立ちはこう:

- **下がる向き（多数派、990 延べ）**: ヒゲが `heightAbs` の**外側の端点**を押し広げる。
  分子（終値差）は不変なので比は下がる。素直な向き。
- **上がる向き（160 延べ）**: 形成中の `allPoints` は `current.extremePrice` に**終値**を置くので、
  **その終値が 5 点の極値になっている**構造がある（triple_bottom なら 5 点の最大、
  triple_top なら最小）。高安に置き換えると極値が他の点に戻り、**分母 `heightAbs` が縮んで
  比が上がる**。上の反例は `heightAbs` が縮んで比が **1.0 を超えた**——
  #178 項目 4 の「`spreadRatio` に 1.0 の上界は無い」がここでも成立する。

**したがって「形成中の比は完成後の比の下界（あるいは上界）」という主張はどちらの向きでも書けない。**
形成中に配線するなら、形成中の idiom（終値）で測った比に閾値を掛けるのであって、
「完成後にどうなるか」の代理として使ってはいけない。

## 6. 波及（§10 の §5 が実測）

- **`FORMING_*` 係数には触らない。** 3 係数はいずれも `tolerancePct` 由来だが、
  高さ相対のゲートは**足すだけ**で他の係数に依存しない。機械的な確認として、
  新ゲートより前に置かれた 9 個の理由コードが**ケース単位で 1 件も減っていない**ことを見た
  （減っていれば理由の横取り）。件数の**増加**（例: `forming_bars_out_of_range` +7,661）は正常で、
  ゲートが `continue` するぶんループが先のペアまで回り続けるため。
- **cap（200 件）**: 新理由コードは飽和ケースでも 85.7〜100% が cap 内に残る。
  飽和ケース数の増加は最大 +31 / 3,672。押し出されるのは既存の棄却理由側で、
  #180 の「押し出しは棄却理由から始まる」がそのまま働いている。
- **`confidence`**: 落ちる側と残る側の分布が同一（min 0.50 / p50 0.59 / max 0.59）で、
  高 confidence 側に偏って落とすことは無い。`confidence` × `spreadRatio` の相関は **−0.41**。
  `rawConfidence` は `currentDiff` しか見ておらず `spreadRatio` の分母（パターン高さ）を
  一切見ていない。**採点式は変えず、ゲートを足すだけ**で整合する。

## 7. Phase 2 への案と推奨（決定はしない）

### 前提: 帰属の切り分けが要る

§8 の目視判定で落ちる 34 実体のうち **24 実体は「3 点目がネックラインの誤側にある」**、
つまり `validateMainPointsNecklineSide`（#216 Phase 2。**完成済みには配線済み・形成中には未配線**）が
本来の帰属。**高さ相対のゲートが単独で拾う「呼べない」形は 6 実体**
（§8 の #2 / #6 / #10 / #11 / #14 / #20）で、その代わり**「呼べる」3 実体も落とす**。

この重なりを見ずに「34 実体落ちる」だけで案 A を決めると、**別のゲートの仕事を
高さ相対のゲートに肩代わりさせる**ことになる（理由コードの帰属が誤り、という #178 項目 3 と
同じ失敗の形）。

### 案 A: `validateLevelSpread` を形成中 2 経路に足す。閾値は完成済みと同じ 0.5

**推奨（主）。** ただし**上の帰属の切り分けを同じ Phase で行うこと**を条件にする。

根拠:

1. **「形成中 ⊇ 完成済みの厳しさ」の回復。** 実体 34 件が「形成中として出るのに、
   同じ 2 点で完成した瞬間に落ちうる形」で、**完成済み経路の高さ相対棄却が実際に出ている構造が
   18**（完成せず落ちた 15 + 完成もするが棄却も出す 3。§4-4）。利用者に見せている「トリプルトップ形成中」が
   定義上トリプルトップになれない、という状態が実データで起きている。
2. **閾値を独自に決める根拠が無い**（§4-2）。分布に空白帯が無い以上、
   0.5 以外の値を選ぶ理由は「効きすぎるから緩めた」でしかなく、#176 が守った基準を満たさない。
   **完成済みと同じ値にしておけば「なぜその値か」の説明が既存の docstring 1 つで済む。**
3. **誤りの検出可能性が非対称**（#178 項目 4 と同じ論法）。誤って弾けば `view=debug` に
   理由コードが出る（§6 のとおり cap 内に 85.7〜100% 残る）。誤って通せば無音。

**コスト**: 正味 −1,250 延べ / 構造 111 → 95。**呼べる 3 実体を落とす**（§8）。
**合成コーパスは 0 件差**なので、既存テストのベースラインへの影響は実データ fixture の
スナップショットだけに出る。

### 案 A′: 先に `validateMainPointsNecklineSide` を形成中に配線し、残差を測り直す

**案 A と併せて検討する価値がある。** 24 / 34 実体がこちらで落ちるので、
配線後に残る高さ相対の効き先は 10 実体（呼べない 6 / 保留 1 / 呼べる 3）まで縮む。
そのうえで案 A を当てるかを決めるほうが、理由コードの帰属が正しくなる。

ただし **#216 Phase 2 のスコープは完成済み経路だった**ので、形成中への配線は別 issue に
切るのが筋（本メモは「そういう破れがある」ところまでを報告する）。

### 案 B: 足すが `maxRatio` を緩める（第 3 引数で経路別に渡す）

**採らない。** §4-2 のとおり分布から根拠が出ない。0.6 なら 1,273 延べ / 0.75 なら 309 延べと
なだらかに減るだけで、どこにも切れ目が無い。「形成中は緩くてよい」という設計判断を
数値化する試みになるが、**その判断が言っているのは「同水準かの判定」であって
「形と呼べる大きさか」ではない**（#169 / PR #170 の整理）。`spreadRatio` は後者に属する。

### 案 C: 何もしない

**次点。** 採るとしたら根拠は「形成中は早期警告なので、完成できない形を見せても
害より益が大きい」という**設計判断**であって、計測ではない。**主指標が 0 件でないので、
「実データに不整合が無いから」という理由では閉じられない。**

採る場合は、`detect_triples.ts` の形成中経路の注記に
「高さ相対の hard gate を**意図的に**入れていない。実測では accepted の実体 34/48 件が
完成済みの 0.5 を超え、うち 24 件はネックラインの誤側でもある」と書き、
次に読む人が「見落とし」と誤読しないようにすること。

### 理由コードは A / B とも新設する

`forming_peak_spread_vs_height_excess` / `forming_valley_spread_vs_height_excess`。
完成済みの `peak_spread_vs_height_excess` を流用すると、#193 / PR #194 の
**`▼ reason 横断合計`（type を畳んで reason だけで合算する行）で形成中と完成済みが
1 つの数字に潰れる**（#178 本文の注意）。本 Phase の ablation もこの新設コードで測っている。

### 形成中 double は本 issue に混ぜない

§10 の §4 のとおり量が小さい（`spreadRatio > 0.5` は実体 1 件）うえ、
**2 経路で主構成点の取り方が非対称**（§2 の結論 14）なので、配線するならその非対称そのものを
先に整理する必要がある。**別 issue。**

## 8. 目視判定（`maxRatio = 0.5` で落ちる 34 実体）

判定は「**トリプルの形成中として妥当か**」の 3 値（呼べる / 呼べない / 保留）。
材料は §10 の §3-3（主構成点の `終値(高安)`、中間点の高安、`spreadAbs`（水準帯）、

### 判定の基準

`MAX_LEVEL_SPREAD_RATIO` の docstring が言うとおり、
**`spreadRatio > 0.5` は「水準帯が押しより厚い」と同値**。そのうえで:

- **呼べない** — 次のいずれか。
  - **(N) 主構成点がネックラインの誤側**（`validateMainPointsNecklineSide` の判定と同じ）。
    「同じ水準に 3 回当たった」ではなく「3 点目がネックラインまで来ている／割っている」形。
  - **(N′) ネックライン側は通るが余裕がゼロ**（誤側との差が水準の 0.15% 未満）。
    実質 (N) と同じ形で、判定が丸めの側に落ちているだけ。
  - **(P) 押しが名目的** — 第 1 押しが 1% 未満かつ水準帯の半分未満。2 つの主構成点が
    実質同じ山／谷で、「3 回当たった」の 1 回目と 2 回目が分離していない。
  - **(M) 単調な階段** — 切り上がり／切り下がりが 3 点で単調。
    §3-2 のとおり `FORMING_STAIR_STEP_LIMIT` は片側しか見ていないので素通りする形。
- **呼べる** — ネックライン側に余裕があり、非単調で、押しが水準帯と同等以上に実体を持つ。
  **閾値 0.5 が厳しすぎる側の候補。**
- **保留** — 上のどちらとも言い切れないもの。

### 5. 波及の確認

#### 5-1. `FORMING_*` 係数の独立性

形成中の 3 係数はいずれも `tolerancePct` から派生している:

| 係数 | 値 | 実効閾値の式 |
|---|---|---|
| `FORMING_TOLERANCE_MULTIPLIER` | 1.2 | `tripleTolerancePct = tolerancePct × 1.2` |
| `FORMING_LEVEL_SPREAD_FACTOR` | 1 | `levelSpreadLimit = tripleTolerancePct × 1` |
| `FORMING_NECKLINE_SPREAD_FACTOR` | 1 | `necklineSpreadLimit = tolerancePct × 1` |
| `FORMING_STAIR_STEP_LIMIT` | 0.02 | `tolerancePct` 由来ではない固定値。**計測時点では片側しか見ていなかった**——`triple_top` の切り上がりと `triple_bottom` の切り下がりだけで、逆向きの単調列は素通りしていた（**#263 で両向きになった**。値は据え置き） |
| `FORMING_MIN_CONFIDENCE` / `FORMING_MAX_CONFIDENCE` | 0.5 / 0.59 | 採点の下限・上限（§5-3）。本ゲートは採点式を変えないので不変 |

高さ相対のゲートを**足すだけ**なら他の係数に触らない。それを機械的に確かめるため、ablation ビルドで**新ゲートより前に置かれた棄却理由の件数**を base と突き合わせる。

**判定は「一致」ではなく「減っていないこと」。** 新ゲートは棄却時に `continue` するので、base なら成功して `return` していたケースで**ループが先の（より古い）ペアまで回り続ける**。その追加の周回が既存の理由コードを新たに積むため、**件数は増える方向にしか動かない**のが正常。**減っていたら**それは新ゲートが既存の理由を横取りしている証拠になる（配置規約違反）。

| 新ゲートより前の理由コード | base | ablation (0.5) | 増減 | 減ったケース数 |
|---|---:|---:|---:|---:|
| `forming_stair_step_up` | 13002 | 13992 | +990 | 0 |
| `forming_stair_step_down` | 4980 | 4980 | +0 | 0 |

**減ったケースは 1 件も無い。** 新ゲートは既存の棄却理由を横取りしていない。増加分はすべて「base では成功して `return` していた周回が、ゲートの `continue` で続いたこと」による。

形成中 triple の `rawConfidence = (1 − currentDiff / tripleTolerancePct) × 0.8` は**価格相対**を使っている。ゲートを足しても採点式は変えない前提なので、「落とす候補が高 confidence 側に偏っていないか」を見る。

|---|---:|---|
| `confidence` × `spreadRatio` | -0.4142 | 0 に近いほど**採点式は高さ相対を代理できていない**（＝ゲートは採点式と独立な情報を足す） |
| 価格相対の使用率 × `spreadRatio` | 0.6525 | 1 に近いほど価格相対のゲートで高さ相対を代用できる |

`confidence` は `currentDiff`（現在値と 2 山平均の差）だけを見ており、`spreadRatio` の分母（パターン高さ）を一切見ていない。**採点式は変えず、ゲートを足すだけ**という前提と整合する。

## 11. 決定（2026-09-09）— **案 C（不採用）**

> §1〜§10 は Phase 1（PR #260、`main` d86fb2b 時点）の計測とその読み。本節はそのあとに
> #261 / #263 で帰属を正したうえで下した**結論**で、[#178 項目 1 の決定コメント][decision]の要約。

**`validateLevelSpread`（高さ相対の hard gate、`MAX_LEVEL_SPREAD_RATIO` = 0.5）は形成中 triple の
2 経路に配線しない。** §7 の案 C を採り、案 A（0.5 で配線）/ 案 B（緩めた閾値）は採らない。

### 根拠 — #261 / #263 後の残差 17 実体

| 残差 17 実体の内訳 | 実体 |
|---|---:|
| 本来は他のゲートの仕事（ネックライン誤側 8 / 誤側との差 0.15% 未満 3 / 単調だが閾値の直下 1）で、別の終端窓で生き残っているもの | 12 |
| 高さ相対ゲートが単独で拾うもの | 5 |
| うち目視（§8）で「**呼べる**」 | **3** |

- 中間決定の判断軸「残差に『呼べる』3 実体が残ったままなら案 C」に該当する。
- 案 A を採ると **12 実体を「高さ相対」の理由コードで落とす**ことになり、中間決定が避けようとした
  帰属の誤り（項目 3 と同じ失敗の形）そのものになる。
- 単独で拾う 5 実体のうち 3 実体が「呼べる」ので、**#249 の基準（示せていないうちは検出を減らさない）**に
  照らして検出を減らす根拠が無い。
- **分布に空白帯が無い**（§4-2）ので 0.5 以外の閾値を選ぶ根拠も無い（案 B は不採用）。

### 残る破れ

**「形成中 ⊇ 完成済みの厳しさ」の破れ（§3）はこのまま残る。** ただしこれは**設計判断としての不採用で
あって見落としではない。** 次に読む人が誤読しないよう、注記を 2 箇所に置いた。

- `tools/patterns/detect_triples.ts` の `FORMING_LEVEL_SPREAD_FACTOR` の docstring（形成中 2 経路
  `tryFormingTripleTop` / `tryFormingTripleBottom` の docstring から `{@link}` で辿れる）
- `docs/tools.md`「形成中 triple の同水準判定に高さ相対のゲートは無い（#178 項目 1。意図的）」

なお「形成中は完成済みより緩くてよい」という一般論は本件の根拠**ではない**。#169 / PR #170 の整理の
とおり、緩めてよいのは「同水準かの判定」であって「形と呼べる大きさか」ではなく、`spreadRatio` は
後者に属する（§7 案 B）。本件が不採用なのは、上の実測で「配線すると帰属が誤り、妥当な形を落とす」ことが
示されたからである。

### 再開条件

`scripts/measure_forming_triple_level_spread_178.ts` を再実行し、残差の内訳を出し直すところから始める
