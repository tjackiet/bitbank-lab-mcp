# `necklineAt` の外挿クランプ（issue #211 Phase 1・実測ログ）

`necklineAt`（`tools/patterns/detect_hs.ts:193`）は 2 定義点を通る直線を**クランプせず外挿する**。
[issue #211](https://github.com/tjackiet/bitbank-lab-mcp/issues/211) Phase 1 として、
外挿の実態（距離・起点のずれ・傾き）と、クランプを入れた場合に何がどれだけ動くかを
**消費者の系統ごとに分けて**測る。

**本ログは計測のみで、リポジトリのコードは 1 行も変更していない。**
クランプを入れるか / どの系統に入れるかは **Phase 1 では決定しない。**

起票時点の issue 本文は消費者を 2 系統（ブレイク検出・ターゲット起点）と書いているが、
**PR #213（H&S confidence の多軸化）が 3 系統目を追加した**ので、本ログは 3 系統で測る
（[1-1 章](#1-1-necklineat-の消費者は-3-系統ある)）。

## 結論（計測結果の要約。対策の決定は含まない）

1. **外挿は例外ではなく常態。ただし起点のずれ方は type で割れる。**
   ブレイク済みの構造は両 type とも中央値 **17 本**を `p3` の外側へ外挿する。
   ネイティブ（実データ B × `1hour`）で見ると、`head_and_shoulders` の 14 構造は
   **全件が高さ比 25.60% 以上**（中央値 27.02% / 最大 45.38%）ずれており、
   「たまに大きく外れる」ではなく「常にこの程度ずれている」。
   一方 `inverse_head_and_shoulders` の 20 構造は **1.46〜42.49%**（中央値 14.14%）で、
   ゼロ近傍まで含めて広く散る。**「必ず 1/4 以上ずれる」と言えるのは
   `head_and_shoulders` だけ**（[1-3 章](#1-3-起点のずれ)）。
2. **傾きは理論上界 1.25%/本 の 83% まで観測した（上界そのものへの到達は観測していない）。**
   issue 本文が「未検証」とした上界に対し、実測最大は **1.0417%/本**。
   一方**定義点間隔は理論最小の 4 本ちょうどが実在する**ので、
   `HS_NECKLINE_MAX_PCT = 0.05` が 2 点の間隔を制約していないことは数値で確認できた
   （上界に届かないのは `|p1 − p3| / max` が 4.167% で上限 5% に達していないため）。
   ただしこれは合成 fixture（`1hour` ラベル）で、**ネイティブでは最大 0.0944%/本**と 1 桁小さい
   （[1-4 章](#1-4-ネックラインの傾き)）。
3. **3 系統は影響範囲がまったく違う。** (i) ブレイク検出のクランプは `data.patterns` の
   メンバを動かす（`head_and_shoulders` 166 → 124 / `inverse_head_and_shoulders` 162 → 164）。
   (ii) 投影起点のクランプは **`confidence` / `status` / `data.patterns` / `globalDedup` を
   1 件も動かさない**（issue が案 C に課した受け入れ条件を実測で満たす）。
   (iii) `breakoutQuality` のクランプはメンバを動かさないが `confidence` を 1,683 行で動かし、
   `globalDedup` の代表を 53 ケースで入れ替える（[2 章](#2-計測-2-クランプで何が変わるか)）。
4. **(i) と (iii) は足し算にならない。** (i) 単独は confidence を上げる方向
   （上昇 912 行 / 下降 336 行）、(iii) 単独は下げる方向（上昇 441 行 / 下降 1,242 行）、
   両方入れると上昇 1,329 行 / 下降 411 行。`breakoutQuality` の飽和率も (iii) 単独で
   24.1% → 19.5%、(i)+(iii) で **44.7%** と逆に動く。
   **合成効果を単独計測から予測できない**（[2-4 章](#2-4-i--iii-合成)）。
5. **プール値とネイティブ錨で符号が逆になる。** (i) を入れると `data.patterns` の
   `head_and_shoulders` は 940 ケース合計で **166 → 124（−42）** だが、ネイティブ錨
   （実データ B × `1hour` + 実データ A × `1day`）では **51 → 52（+1）**。
   **結論をプール値で書けない**実例（[3 章](#3-計測-3-datapatterns-への影響)）。
6. **#216 Phase 1 の `clamped` 行と完全に一致した。** 構造ゲートに渡すネックラインを
   外挿クランプ付きの線にしたときの「誤った側」件数は `head_and_shoulders` 35 /
   `inverse_head_and_shoulders` 34 構造で、#216 の記載値と全桁一致する。
   役割別の生の行数（右肩 141 / 73、頭 0 / 6）も一致した（[4 章](#4-計測-4-216-との接続)）。

### 計測用複製の作り方

`necklineAt` にクランプを入れる計測なので、本体を書き換えずに測る手当てが要る。
`tools/patterns/detect_hs.ts` を機械的に複製し、以下の 3 点だけを変えたモジュールを作った。

1. 相対 import のパスを複製先から解決できるように書き換える（ロジックには触らない）。
2. `necklineAt` の**直後**に系統別のスイッチとクランプ関数を足す。
3. 4 種の呼び出し箇所（[1-1 章](#1-1-necklineat-の消費者は-3-系統ある)の (i) / (ii) / (iii)）を、
   スイッチを見る版に差し替える。

```ts
export const CLAMP = { breakout: false, target: false, score: false };
function clampIdx(neckline: NecklinePt[] | undefined, i: number): number {
	// ... 添字を [min(p1.x, p3.x), max(p1.x, p3.x)] に丸めるだけ
}
```

**スイッチを全部 OFF にした複製が、本体の `detectHeadAndShoulders` と 940 ケース全件で
一致することを確認してある**（差分 0 件）。差し替えが挙動を変えていないことの担保はこの 1 点なので、
比較は**本ログが差分を報告するすべての値**を含む全フィールド一致で取っている
（`data.patterns` のメンバ一致ではない）:

| 比較対象 | 内容 | 差分 |
|---|---|---:|
| 検出器の生の出力 | `detectHeadAndShoulders(ctx).patterns` を **JSON 全体**で比較。`breakoutBarIndex` / `breakout` / `status` / `range` / `confirmation` / `outcome` / `breakoutTarget` / `targetReached*` / `targetProgressOmittedReason` / `scoreComponents`（`breakoutQuality` を含む）/ `confidence` / `neckline` / `structureGate` / `structureDiagram` 等 27 キー全部 | **0** |
| `globalDedup` 前の全 type 連結 | 6 検出器の連結結果を JSON 全体で比較 | **0** |
| `globalDedup` 後 | 同上 | **0** |
| `data.patterns`（ライフサイクル絞り込み後） | 同上 | **0** |
| `debugCandidates` の H&S 分 | 棄却理由・`indices` / `points` まで比較 | **0** |

**生の出力の段で取っているので、`globalDedup` が捨てた候補やライフサイクル絞り込みで
落ちた行も比較対象に入っている**——「出力に残ったものだけ一致」ではない。

## 1. 計測 1: 外挿の実態

### 1-1. `necklineAt` の消費者は 3 系統ある

| 系統 | 位置 | 呼び出し | 外挿される添字 | 影響先 |
|---|---|---|---|---|
| **(i)** | `:424`（`findHsBreakoutIdx` 内） | `necklineAt(neckline, k)` | 走査中の足 `k`（`p4 + 1` 〜 `p4 + 30`） | `breakoutIdx` → `status` / `range.end` / `confirmation` / `breakout` / `outcome`、および `breakoutClose` 経由で `confidence` |
| **(ii)** | `:254`（`necklineAtOr`。`:247` の `necklineProjectionTarget` が使用） | `at(anchorIdx)` | ブレイク足、未ブレイクなら右肩 `p4` | `breakoutTarget` / `targetReached*` / `targetProgressOmittedReason` |
| **(iii)** | `:832` / `:1036` / `:1293` / `:1513` | `necklineAt(neckline, breakoutIdx)` → `buildHsScore` の `necklinePrice` | ブレイク足 | `breakoutQuality` 軸 → **`confidence` に直接** |

**(iii) は #211 起票時に存在しなかった経路**で、PR #213 が 4 箇所を追加した。
クランプは `confidence` を (i) 経由と (iii) 直接の**2 ルート**で動かす。

外挿がかからない経路もある。**どちらも構造上そうなるので実測の対象ではない**:

- **`necklineProjectionHeight` の `nlAtHead`**（`:276`）は内挿。頭 `p2` は定義点 `p1` / `p3` の
  **間**にあるので、クランプしてもしなくても同じ値になる。
- **relaxed 経路のネックライン**（`:1219` / `:1441`）は `nlY` を両端に置いた**水平線**なので、
  `necklineAt` が添字によらず定数を返す。クランプは恒等変換になる。
  （本コーパスでは relaxed の accepted が 0 件なので、いずれにせよ発火しない。#205 と同じ。）

`inverse_head_and_shoulders` `14-16-18-20-22` で、定義点間隔 **4 本**・`|p1 − p3| / max` **4.167%**
→ 傾き **1.0417%/本**。上界に届かない差は間隔ではなく水平度で、
**間隔は理論最小の 4 本ちょうど**が実在する（`HS_NECKLINE_MAX_PCT = 0.05` が 2 点の間隔を
制約していないことは、この 1 点で数値的に確認できる）。5% 側は最大 4.990% までで、
**両方を同時に極める構造は出ていない。**

ただし**傾きの最大値と外挿距離の最大値は同じ構造では起きていない。**
この構造の外挿距離は 4 本（`p3` = 20、ブレイク = 24）にとどまる。
`|p1 − p3| / max` が上限 5% に張り付いた実データ A の 5 構造
（`9-13-17-27-38` / `9-13-17-27-42` / `9-13-17-27-47` × `4hour` / `1hour` ラベル。
傾き 0.3565%/本）は**いずれも `breakoutIdx = -1`（未ブレイク）**で、
(i) のクランプの対象にならない。**傾きが理論上界にどこまで近いかは、
そのまま「起点のずれの最悪値」にはならない**——実際に効くのは傾き × 外挿距離で、
それを測ったのが [1-3 章](#1-3-起点のずれ)。そちらの最大は高さ比 385.68% で、
**傾き 0.1944%/本**（本節の最大の 1/5）× 外挿 16 本 ÷ 高さ 101,029 から出ている。

**ネイティブでは最大 0.0944%/本**で、上界より 1 桁小さい。
**「上界の 83% まで届く形は作れるが、ネイティブ時間足の実データには出ていない」**
が本節の結論。上界そのものに到達する形（間隔 4 本 かつ `|p1 − p3| / max` が 5% ちょうど）は
**本コーパスでは観測していない**——実現不能かどうかは、このコーパスからは言えない。

**全桁一致したので、#216 の結果は再現でき、両計測は整合している。**
ただし**これは「どちらにも誤りが無い」ことの証明ではない**——両者は同じコーパス・同じ
検出器・同じ「誤った側」の定義を共有しているので、**共通の前提や定義に誤りがあれば
同じ値で一致する。** 独立に確認できたのは「#216 の数値が本ハーネスからも出る」ことまで。

`line` の逆 H&S の頭 6 行（#216 が付録 No.91 / 93 / 95 とした `1min` ラベルの退化した 3 構造）は
**クランプしても消えない**——頭は定義点 `p1` / `p3` の間にあるのでクランプが恒等変換になるため
（[1-1 章](#1-1-necklineat-の消費者は-3-系統ある)）。#216 が `clamped` を「ゼロ近傍の集団が消える」と
書いた根拠は右肩側の 615 → 73 行の縮小であって、頭の 6 行はどの基準でも残る。

**`clamped` が top / bottom で対称になる（35 / 34）のは、外挿の向きによる系統的な偏りが
消えるため。** [2-1 章](#2-1-i-ブレイク検出のみクランプ)で `head_and_shoulders` が
一方向に消える（消失 107 / 発生 0）のと同じ機構の裏返しで、
**#216 の「`clamped` を選ぶと閾値が非任意になる」という判断は本計測と整合している。**

## 6. 計測の限界

- **標準コーパスの「時間足」はリサンプリングではなくパラメータのラベル。**
  同じ終値列を `1min` として扱った結果も含む（#205 / #216 の同名の注記と同じ限界）。
  本文の錨はすべてネイティブ時間足サブセットで、プール値は「ラベルを含めた分布」として読むこと。
- **relaxed 経路は本コーパスで accepted 0 件。** relaxed のネックラインが水平でクランプが
  恒等変換になることは**構造から言える**（[1-1 章](#1-1-necklineat-の消費者は-3-系統ある)）が、
  実データでの確認ではない。
- **ハーネスは `data.patterns` までで、`buildStatistics` / aftermath の差分は測っていない。**
  (i) は `range.end` を 1,393 行で動かすので、統計ブロックにも影響が出るはず。
  Phase 2 で (i) を採る場合は別途測ること。
- **`tests/fixtures/detect_patterns_1hour_data_patterns_baseline.json` は本 Phase では触っていない**
  （コード変更が無いため）。(i) / (iii) を採る場合は更新が必要で、
  `tests/detect_patterns_data_patterns_regression.test.ts` の docstring の更新履歴の表に
  1 行足すこと（#207 で入ったルール）。
